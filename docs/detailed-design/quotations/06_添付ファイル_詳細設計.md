# 添付ファイル 詳細設計書

> 見積管理の全画面共通のやり取り（コメント）に付随する添付ファイル機能の仕様。
> やり取り機能そのものは [00_共通仕様_詳細設計.md](./00_共通仕様_詳細設計.md) §4 を参照。
> 本書はデプロイ先（さくらのレンタルサーバー・共有）を前提とした確定仕様である。

## 1. 上限

- 1ファイル **10MB** ／ 1送信 **5ファイル**（合計目安50MB）。

## 2. 許可拡張子（ホワイトリスト）

| 分類 | 拡張子 |
| --- | --- |
| 画像 | `jpg` `jpeg` `png` `gif` `webp` `heic` `heif` |
| 文書 | `pdf` `txt` |
| Office | `xlsx` `xls` `docx` `doc` `pptx` `ppt` `csv` |
| CAD・図面 | `dwg` `dxf` `jww` `jwc` `sfc` `p21` |
| 圧縮 | `zip` |

- **拒否**：`exe/bat/cmd/com/msi/sh/ps1/php/phtml/js/html/htm/svg` などホワイトリスト外は一律拒否。
  とくに SVG はインライン表示で XSS になるため不許可。

## 3. クリック時の挙動（統一）

- **拡張子に関わらず、クリックしたら常にダウンロード**する（`Content-Disposition: attachment`・元ファイル名で保存）。
- 新しいタブでのプレビュー表示は行わない。

## 4. チャット内の表示

- **画像**：吹き出しに**サムネイルを表示**する。クリックで元ファイル（圧縮済み）をダウンロード。
- **画像以外（HEIC含む）**：種別アイコン＋ファイル名＋サイズを表示。クリックでダウンロード。
- 自分の投稿は右寄せ・相手は左寄せ（現行UI踏襲）。

## 5. 画像圧縮・サムネイル（GD）

対象：`jpeg/png/gif/webp`（`heic/heif` はGD非対応のため圧縮せずそのまま保存）。

**アップロード時のサーバ処理**
1. `getimagesize()` で寸法取得 → **総ピクセルが約40MP超なら圧縮をスキップ**して元を保存
   （共有サーバのメモリOOM回避。`memory_limit` が低いプランでは閾値を下げる）。
2. EXIF Orientation を読み、正しい向きへ回転してから EXIF を破棄。
3. **長辺 > 1920px ならアスペクト比維持でリサイズ**。
4. 再エンコード：JPEG→品質**82** ／ PNG（透過）→リサイズのみで維持 ／ WebP→維持。
5. **サムネイル生成**：長辺**400px**・JPEG品質80。→ チャット吹き出しに表示。
6. 元（圧縮済み）はダウンロード用に保持。

## 6. 保存レイアウト（DB列は増やさずパス規約）

```
comments/{itemId}/{uuid}.{ext}        … 元（画像は圧縮済み）  ← t_attachments.file_path
comments/{itemId}/thumbs/{uuid}.jpg   … サムネ（画像のみ・規約パス）
```

- `t_attachments` は現行列のまま（`file_path` / `original_name` / `mime_type` / `size` / `user_id`）。
  テーブル定義は felix_total 側スキーマのため、列追加はしない。
- 保存名は **UUID化**、元名は `original_name` で保持（ダウンロード時に復元）。

## 7. 配信（`CommentAttachmentController`）

| 用途 | エンドポイント | 挙動 |
| --- | --- | --- |
| ダウンロード | `quotation-management.comment-attachments.download` | `attachment` 配信。全ファイル共通のクリック先 |
| サムネ表示 | `quotation-management.comment-attachments.thumb`（新規）or 規約パス配信 | 画像サムネの `<img>` 表示用にインライン配信（画像のみ） |

- すべて `auth:admin` 認証付きで Laravel から直接ストリーム。
- インライン配信は**サムネイル画像に限定**（SVG/HTML はインライン配信しない）。

## 8. API レスポンス（`EstimateChatFile`）

| フィールド | 内容 |
| --- | --- |
| `id` / `name` / `mime` / `size` | 現行どおり |
| `isImage` | 画像（サムネ生成対象）か |
| `thumbUrl` | サムネURL（画像のみ・無ければ null） |
| `downloadUrl` | ダウンロード用URL（全ファイルのクリック先） |

- ※ プレビュー（新タブ表示）を廃止したため、インライン表示用 `url` ・ `openable` フラグは持たない。

## 9. バリデーション

**バックエンド（`StoreQuotationMessageRequest`）**
```
files   : nullable | array | max:5
files.* : file | max:10240   // 10MB
          | extensions:jpg,jpeg,png,gif,webp,heic,heif,pdf,txt,
                       xlsx,xls,docx,doc,pptx,ppt,csv,
                       dwg,dxf,jww,jwc,sfc,p21,zip
body    : nullable | required_without:files | string | max:2000
```

> **実MIME整合（拡張子偽装対策）の実装方針**
> `extensions` ルールはクライアント拡張子をホワイトリスト照合し、`svg/exe/php` 等を拒否する。
> 一方、CAD（`dwg/jww/…`）や `zip` は環境依存で実MIMEが `application/octet-stream` に潰れ、
> `mimetypes` ルールで一律照合すると正当なファイルを誤って弾く。そのため **`mimetypes` は一律には課さず**、
> 画像に限り保存時に `getimagesize()` で実体を検証し（§5・§10 の `ImageCompressor`）、
> 「画像を騙る非画像」を排除する。非画像は拡張子ホワイトリスト＋常時ダウンロード配信（§3・§7）で安全側に倒す。

**フロントエンド（送信前チェック・新規）**
- 拡張子ホワイトリスト外・10MB超・5件超をアップロード前に弾いてメッセージ表示。

## 10. セキュリティ

- ホワイトリスト＋**実MIMEと拡張子の整合チェック**（拡張子偽装対策）。
- 保存名 UUID 化でパストラバーサル無効化。
- **配信は常にダウンロード**（インラインはサムネイル画像のみ）。SVG/HTML はインライン配信しない。
- 画像の再エンコードで埋め込みスクリプト等を除去（副次効果）。

## 11. サーバ設定（さくら `.user.ini` / コントロールパネル）

```ini
upload_max_filesize = 12M
post_max_size       = 64M      ; アプリ上限(10MB×5)は必ずこれ未満
max_file_uploads    = 20
memory_limit        = 256M     ; GD画像処理の余裕（重要）
max_execution_time  = 60
```

- アプリ上限（10MB×5）は**必ず `post_max_size` 未満**にする。超過すると `$_FILES` が空になり無言で失敗する。
  とくに `upload_max_filesize` が小さい（例: 既定 2M）と、大きめの添付が PHP レベルで弾かれ
  `file` バリデーションで 422 になり「送信に失敗しました」となる。必ず上表の値へ引き上げること。
- 本番プランで `phpinfo()` を出して実値を確認する。`memory_limit` が低ければ §5-1 の圧縮スキップ閾値を下げる。
- **開発環境（Docker）** は本設定を `fix/.docker/php/uploads.ini`（`conf.d` へ配置）で反映し、
  GD/EXIF 拡張は `Dockerfile.dev` / `Dockerfile`（`gd` `exif`）で導入する。変更後は `docker compose up -d --build` で再ビルドが必要。
