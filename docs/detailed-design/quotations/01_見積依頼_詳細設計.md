# 見積依頼 詳細設計書

> 共通の仕組み（ヘッダー / フィルタ / やり取り / iframe / テーマ / 送信・エラー方針）は
> [共通仕様_詳細設計.md](./00_共通仕様_詳細設計.md) を参照。本書は本画面固有の差分を記述する。

## 1. 概要

- **画面名**: 見積依頼【FELIX→業者依頼前】
- **mode**: `quote-request`
- **操作ロール**: 建設部、システム開発、administrator
- **目的**: FELIX が業者へ相見積を依頼する前段。移行済み（`source_id` あり）の見積先に対して、
  見積依頼（相見積依頼）を送信する。何度でも再依頼できる。

業務フロー上の位置づけ:

```
【見積依頼】 送信──▶ 業者選定 ──▶ 部長承認 ──▶ 部長取消申請 ──▶ 部長取消承認
```

## 2. 機能説明

本画面の操作は、**画面上部の「絞り込み・操作バー」のボタン**と、**明細（各行）のボタン**の
2つのボタン群から行う。以下ではボタンごとに実行される処理を分けて記載する。

前提となる一覧表示: 依頼可能な見積先（移行済み＝`source_id` あり）を「実行予算 → 項目 → 見積先」の
明細で一覧表示する。各見積先の送信回数（`sendCount`）で未依頼／依頼済みを判別し（0回＝未依頼、
依頼済みでも再依頼可）、「送信回数」と右端に「最終依頼日時」を表示する。（→ §4, §5）

### 2.1 絞り込み・操作バーのボタン（画面上部）

| ボタン / 操作 | 実行される処理 | 参照 |
| --- | --- | --- |
| 絞り込み（検索） | 実行予算名 / 項目名 / 見積先名でサーバ側フィルタし、一覧を再取得する。 | §8, 共通仕様 §3 |
| 回答状態フィルタ | 全て / 見積回答あり / 見積回答なし（最新相見積履歴の有無）でサーバ側フィルタする。 | §8, 共通仕様 §3 |
| コメント有無フィルタ | 全て / コメントあり / コメントなしでサーバ側フィルタする。 | §8, 共通仕様 §3 |
| 未依頼のみ表示 | 未依頼（送信回数0）の行だけにクライアント側で絞り込む（サーバ再取得なし）。初期表示は ON。 | §6.2 |
| 仮選定のみ表示 | 仮選定した行だけにクライアント側で絞り込む（サーバ再取得なし）。 | §6.2 |
| 明細を全て開く / 閉じる | 全実行予算カードの明細を一括で開閉する。 | §5 |
| 全て選択 / 全て解除 | 表示中の選択可能な行の「見積依頼」チェックを一括で ON / OFF する。 | §7.1 |
| 見積依頼送信 | チェックした見積先へ相見積依頼を一括送信する。felix_total の既存処理を呼び出して実行する。 | §7 |

**検索項目（絞り込み検索フォーム）**: 下記3項目を入力し「絞り込み検索」ボタンで送信すると、
条件に一致する一覧をサーバから再取得する。いずれも**部分一致（LIKE）**で、空欄の項目は条件から除外する。

| 入力欄（画面ラベル） | 検索対象 | 条件 |
| --- | --- | --- |
| 物件名 | 実行予算名（`t_buildings.building_name`） | 部分一致 |
| 項目名 | 費用項目名（`t_building_cost_items.item_name`） | 部分一致 |
| 見積先 | 見積先の会社名（`company_name`） | 部分一致 |

> 上記の検索フォームに加え、操作バーの「回答状態フィルタ」「コメント有無フィルタ」も
> サーバ側の絞り込み条件として併用される（各ボタンの行を参照）。

## 4. 表示データ・抽出条件

本画面は他画面と異なり `approval_status` に依存しない。

- 対象見積先: `source_id` が非 NULL（＝felix_total から移行済みで依頼可能）。
- 未依頼／依頼済みの区別は**送信回数**（`t_cost_quotation_requests` の件数 = `requests_count`）で行う。
  一覧取得時に `withCount('requests')` で付与する。未依頼・依頼済みの両方を並べ、画面側のトグルで絞り込む。
- **最終依頼日時**は同テーブルの `requested_at` の最大値（= 直近の依頼送信時刻）。
  一覧取得時に `withMax('requests', 'requested_at')` で付与する（属性名 `requests_max_requested_at`）。
  未依頼（0 件）は NULL になり、画面では「—」を表示する。
- 相見積額（`quotePrice`）は最新の相見積履歴（`latestHistory.amount_excluding_tax`）を表示する。
- 回答状態フィルタ（`answer`）が使える（最新相見積履歴 `is_latest` の有無）。

`BuildingQuotationResource` による主な行フィールド:

| フィールド | 内容 |
| --- | --- |
| `sendCount` | 送信回数（`requests_count`）。0=未依頼 |
| `lastRequestedAt` | 最終依頼日時（`requests_max_requested_at` を `Y/m/d H:i` 整形）。未依頼は `null` |
| `requested` | `sendCount > 0`（依頼済みか） |
| `provisional` | 仮選定（`is_drafted === 1`） |
| `quotePrice` | 相見積（最新履歴の税抜額） |
| `vendorUrl` | 業者マイページ（`estimate_edit_url`、別タブ） |
| `addVendorUrl` | 業者追加（`add_vendor_url`、iframe） |
| `vendorDetailUrl` | 見積先の詳細（`vendor_detail_url`、iframe） |

## 6. 固有機能

### 6.1 仮選定

FELIX が「依頼したい業者」に付ける印。チェック時に即時保存する。

- 保存先: `t_cost_quotations.is_drafted`（0/1）。既存の `vendor-selection/provisional` API を流用。
- フロー: チェック → `provisionalOverride` を楽観的に反映 → `router.post(provisionalRoute, { companyId, drafted })`
  （`only:['flash']`, `preserveState`, `preserveScroll`）→ 失敗時は元に戻す。
- 表示: サーバ値（`row.provisional`）＋ローカル上書き（`provisionalOverride`）を合成した `provisionalKeys` で判定。

### 6.2 クライアント側の表示フィルタ

サーバ再取得なしで `displayProjects` により行を絞る。

- **未依頼のみ表示**（`unrequestedOnly`）: `sendCount === 0` の行だけ。**初期表示で ON**（未依頼から着手できるように）。
- **仮選定のみ表示**（`provisionalOnly`）: 仮選定（`provisionalKeys`）の行だけ。
- 両方 OFF なら全件。空表示時のメッセージは条件で出し分け（未依頼なし／仮選定なし／対象なし）。

## 7. 送信処理（見積依頼送信）

### 7.1 入力・フロー

1. 未依頼（または再依頼したい）行をチェック → ヘッダー「見積依頼送信（n）」が活性化。
2. 送信 → `SendQuoteRequestRequest` へ `companyIds`（`t_cost_quotations.id` 配列）を POST。
3. `QuoteRequestService::send()` → `BuildingQuotationRepository::recordQuoteRequests()`。

バリデーション（`SendQuoteRequestRequest`）:
- `companyIds`: required / array / min:1
- `companyIds.*`: integer / distinct / `exists:t_cost_quotations,id`

### 7.2 felix_total 連携（`recordQuoteRequests`）

新スキーマの見積先を旧 ID へ写像し、felix_total の見積依頼処理をサーバ間 HTTP で実行する
（トークン発行＋履歴作成＋業者へメール送信）。

- felix_total は `"{estimate_units.id}:{estimate_unit_companies.id}"` 形式を要求するため、
  見積先 `source_id`（旧 `estimate_unit_companies.id`）と項目 `source_id`（旧 `estimate_units.id`）の両方を使う。
- 移行元（`source_id`）の無い見積先は依頼不可のため除外する。
- ペアを `FelixTotalQuoteRequestGateway::orderEstimate($pairs)` へ渡す。
- 参照: `docs/architecture/backend.md`「3.5 外部システム連携」。

### 7.3 応答

- 成功（1件以上）: `back()->with('success', "見積依頼を送信しました。（n件）")`。
- 0件: `back()->with('error', '見積依頼を送信できませんでした。選択した見積先は既に依頼済みの可能性があります。')`。
- 例外: Service が `ServiceException` を投げ、トースト（`flash.error`）へ変換。

## 8. 共通機能の利用

- **やり取り（コメント）**: 全画面共通。項目名右の吹き出しから起動（共通仕様 §4）。
- **iframe モーダル**: 「見積先の詳細」「業者追加」。本画面のみ「業者マイページ」を別タブで開く（共通仕様 §5）。
- **フィルタ**: `keyword` / `itemLabel` / `vendor` / `answer` / `comment`（共通仕様 §3）。
