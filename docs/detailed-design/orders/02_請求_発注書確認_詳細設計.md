## 1. 概要

- **画面名**: 【請求】発注書確認【FELIX(建設部部長)】
- **区分**: 請求＝「もらい」／**新規画面（⭐️発注書ボタン押下時に表示される画面を新規作成）**
- **mode**: `billing-order-confirmation`
- **操作ロール**: 建設部部長（`manager_role_slugs`）、administrator（**閲覧のみ**。更新操作は無い）
- **目的**: もらい（請求）の発注書を部長が確認する。業者が発注を承諾すると**発注承諾日**が入る。
  **確認だけを行い、画面からの更新は行わない（表示のみ）。**

業務フロー上の位置づけ:

```
⑥ 業者が「発注承諾」ボタンを押す（業者マイページ・⭐️新規機能）
            │ 発注承諾
            ▼
⑦ 業者選定画面（表示のみ。もらいは選定不要）
            │
            ▼
⑧ 内部処理：発注書に対して受注を承諾する
            │
   ┌────────┴────────────────────────────┐
   ▼                                     ▼
⑨ 業者マイページ 発注タブ            【請求】発注書確認 に「発注承諾日」が入る
   発注書プレビューに「承認済」ハンコ    （本画面）
   以降、業者からの操作ボタンは出ない            │
                                                ▼
                                        納品管理画面へ進む（別シート・未作成）
```

## 2. 機能説明

**本画面は表示のみ**のため、ヘッダーの一括アクションボタン・明細の選択操作は持たない。
一覧は支払系一覧と同じ「実行予算 → 項目 → パートナー」の階層で表示する。（→ §4, §5）

| 項目 | 内容 |

**列ごとの表示元**

| 列 | テーブル.カラム | 経路 |
| --- | --- | --- |
| 項目名 | `t_building_budget_items.name` | `t_billing_partners.building_budget_item_id` |
| パートナー名 | `companies.company_name` | `t_billing_partners.company_id` |
| 発注金額 | `t_billing_orders.subtotal_amount`（合計金額（税別）） | `t_billing_orders.billing_partner_id` |
| 発注承諾日 | `t_billing_orders.contract_approved_at`（請負承認日時） | 同上 |

> **発注書の発行タイミング**: **【請求】見積承認（部長）時**（`BillingQuotationService::approve()`）。
> 承認された最新見積（`t_billing_quotations` の `is_latest`）の金額・明細をそのまま写す
> （もらいは見積＝発注＝請求で同額）。メモ行（`is_memo`）は発注書に載せない。
> 見積の**否認・取消承認**（`CANCELLED` への差し戻し）では発注書も併せて削除する。

## 5. 画面レイアウト（明細テーブルの列）

**支払系（見積管理）の一覧を踏襲**し、実行予算カード → 項目 → パートナーの階層で表示する。
同一項目は項目列を rowspan でまとめる。**列は次の5つだけとし、操作列は持たない。**

| 列 | 内容 | 備考 |
| --- | --- | --- |
| 項目名 | `t_building_budget_items.name` | 同一項目は rowspan。右隣にやり取り吹き出し |
| パートナー名 | 会社名（`companies.company_name`） | iframe リンク（共通仕様 §5） |
| 発注金額 | `t_billing_orders.subtotal_amount`（税別） | もらいは見積＝発注＝請求で同額 |
| 発注承諾日 | `t_billing_orders.contract_approved_at`（⑧ で記録） | 未承諾は「—」 |
| 発注書 | 「発注書」ボタン | 押下でプレビュー（§6.1）。**唯一のボタン** |

> **区分列は設けない。** 区分フィルタで「全て」を選んだときは、支払系一覧と同じ区分バッジを
> **パートナー名セルの中**に表示する（列は増やさない）。逆区分の行は表示のみ（`operable = false`）。
>
> **標準単価 / 予算単価 / 見積額の列は持たない**（もらいは見積＝発注のため、金額は発注金額のみ）。

## 6. 操作仕様

### 6.1 発注書プレビュー

- 「発注書」ボタン押下で felix_total の発注書確認画面（`check_company_list`）を iframe で開く
  （`config('felix.order_document_url')`。物件＝`t_buildings.source_id` で絞り込む）。
  支払側（業者承諾確認・発注実行・発注承認）の「発注書」ボタンと同じ仕組みに揃えた。
- 業者が承諾済みの場合は**「承認済」のハンコ**が押された状態で表示される（felix_total 側の描画）。
- 以降、業者マイページ側には操作ボタンを出さない（felix_total 側の実装）。
- 物件に移行元（`source_id`）が無い場合は URL を組めないためボタンを非活性にする。

> 旧実装にあった「主要項目だけのダミープレビュー」モーダルは廃止した（実帳票を表示するため）。

### 6.2 発注承諾日の記録（⑧ 内部処理）

- 業者が ⑥「発注承諾」を押すと、⑦→⑧ を経て**発注書に対する受注承諾**が記録される。
- 本画面の「発注承諾日」に日付が入った状態になる（システムが自動で更新。画面からの操作は無い）。

## 7. felix_total 連携

- ⑥ の「発注承諾」ボタン、⑨ の発注書プレビュー（承認済ハンコ）は**業者マイページ（felix_total）側の実装**。
- 新Fix 側は ⑧ の内部処理で発注承諾日を受け取る。連携方式（API / DB 直参照）は **TBD**。
- 本画面からの更新は無い（表示のみ）。

## 8.5 画面の表示条件

> 出典: **見積管理_処理フロー**（H〜L 列）。

### アクション

**現時点では次にすべきアクションが無いため表示のみ。**
支払側（業者承諾確認）と同じく、**「ステータス確認」画面へ統合するかは未決**（→ §9）。

### 初期表示条件

- 区分が**請求**
- **見積承認がされた**

### 絞り込み条件

> 表の見方（処理フロー I列の記法）
> - **単一選択**（`・` 区切り）… セグメント／ラジオ。**初期値**の列が画面初期表示時の選択。
> - **チェックボックス**（`・` 区切りなし）… 単独のトグル。**初期値**が ON のものは初期表示時からチェック済み。

| 項目 | 形式 | 選択肢 | 初期値 |
| --- | --- | --- | --- |
| 区分 | 単一選択 | 全て / 請求 | **請求** |
| コメント | 単一選択 | 全て / コメントあり / コメントなし | **全て** |


> **区分の切り替え**
> - **請求**（初期値）… `t_billing_partners` の取引先だけを表示する。
> - **全て** … 請求に加えて `t_payable_partners`（支払）の取引先も**同じ一覧に並べる**。
>   支払行は承認ステータスに関わらず**表示のみ**で操作できない（サーバが `operable = false` を返す）。
>   ただし本画面は請求行も含めて全行が表示のみのため、区分による操作可否の差は生じない。

### 表示する承認ステータス

| ステータス | 条件 |
| --- | --- |
| `APPROVED`（承認済） | かつ **発注テーブル（`t_billing_orders`）にデータがあること** |

> **実装は承諾の有無では絞らない。** 処理フロー（J列）は「業者承諾日時にデータがあること」も
> 条件にしていたが、それでは承諾待ちの発注書を確認できず、§5 の「未承諾は『—』」とも矛盾する。
> そのため**発注書の有無だけ**を条件にし、未承諾は発注承諾日を「—」で表示する。
> 承諾前は【請求】見積取消申請にも同じデータが出るが、取消できるのは承諾前だけなので
> 業務上は矛盾しない（→ [08_請求_見積取消申請](../quotations/08_請求_見積取消申請_詳細設計.md) §8.4）。

### 表示ステータス以外のデータの扱い

**左記のステータスとデータ状態に該当するデータは、見積管理側には表示しない。**
＝ 承諾済みのものは発注管理だけに出す。

### 業者マイページ側の操作

なし（発注承諾は【請求】見積承認の段で行う。
→ [07_請求_見積承認](../quotations/07_請求_見積承認_詳細設計.md) §8.4）。
