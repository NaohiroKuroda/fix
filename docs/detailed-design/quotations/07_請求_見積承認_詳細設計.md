## 1. 概要

- **画面名**: 【請求】見積承認【FELIX(建設部部長)→業者】
- **区分**: 請求＝「もらい」／**新規画面**
- **mode**: `billing-quote-approval`
- **操作ロール**: 建設部部長（`manager_role_slugs`）、administrator
- **目的**: 担当者が作成した請求見積（`APPLIED`）を部長が承認する。
  承認すると `APPROVED` へ進み、**業者へ通知メールを送信**して業者マイページで内容確認できる状態にする。

業務フロー上の位置づけ:

```
③ 見積作成 ──▶【④ 見積承認】──通知メール──▶ ⑤ 業者が内容確認（業者マイページ）
                                                        │
                                                        ▼
                                        ⑥「発注承諾」ボタン（業者・⭐️新規機能）
                                                        │
                                                        ▼
                          ⑦ 業者選定画面（表示のみ）──▶ ⑧ 発注書に対して受注を承諾（内部処理）
                                                        │
                                        ┌───────────────┴───────────────┐
                                        ▼                               ▼
                    ⑨ 発注書プレビューに「承認済」ハンコ     【請求】発注書確認に「承諾日」
```

## 6. 操作仕様

### 6.1 承認（一括）

1. 明細行の「承認する」を押して対象を選択する（複数可）。
2. ヘッダーの「見積承認」で送信する。
3. `t_billing_partners.approval_status` を `APPLIED → APPROVED` へ更新する。
4. 対象の請求先ごとに**業者へ通知メールを送信**する（本文に業者マイページのリンク）。
5. felix_total（業者マイページ）へ見積内容を反映する（§7）。
6. 3〜5 は 1 トランザクション。felix_total 側が失敗したら 3 をロールバックする。

### 6.2 応答

- 成功: `back()->with('success', "見積承認を実行しました。（n件）")`
- 0件: `back()->with('error', '見積承認を実行できませんでした。対象の請求先をご確認ください。')`
- 例外: `ServiceException` → トースト

### 6.3 見積内容の参照

③ で作成した `t_billing_quotations` ＋明細を読み取り専用モーダルで表示する
（項目名 / 数量 / 単位 / 単価 / 課税区分 / 金額 / 合計 / 消費税調整 / 源泉所得税 / コメント）。

## 7. felix_total 連携

- **承認時に新→旧のデータ同期を行う**。現行 felix_total 側に**新規作成予定の API** を呼び出し、
  業者マイページ（見積タブ）で FELIX が入力した金額を業者が確認できる状態にする。
- 処理順は支払側と同じく **「新テーブルを更新 → 現行 API」**。API 失敗時は新テーブルをロールバックする
  （→ [02_支払_業者選定](./02_支払_業者選定_詳細設計.md) §7.2 と同じ方針）。
- 業者マイページ側の**「発注承諾」ボタンは⭐️新規機能**（felix_total 側の実装。本書の対象外）。

### 7.1 通知メール

| 項目 | 内容 |
| --- | --- |

## 8.4 画面の表示条件

> 出典: **見積管理_処理フロー**（H列 初期表示条件 / I列 絞り込み条件 / J列 表示承認ステータス /
> K列 ステータス外表示形式 / L列 業者マイページ）。

### 初期表示条件

- 区分が**請求**
- **見積が作成されているが未承認**

### 絞り込み条件

> 表の見方（処理フロー I列の記法）
> - **単一選択**（`・` 区切り）… セグメント／ラジオ。**初期値**の列が画面初期表示時の選択。
> - **チェックボックス**（`・` 区切りなし）… 単独のトグル。**初期値**が ON のものは初期表示時からチェック済み。

| 項目 | 形式 | 選択肢 | 初期値 |
| --- | --- | --- | --- |
| 区分 | 単一選択 | 全て / 請求 | **請求** |
| 見積作成ずみ | チェックボックス | — | **ON** |
| コメント | 単一選択 | 全て / コメントあり / コメントなし | **全て** |
| 未承認 | チェックボックス | — | **ON** |

> どちらのチェックボックスも初期表示時から ON。初期表示条件（見積が作成されているが未承認）と
> 同じ絞り込みなので、**外すと対象外のデータも見える**という位置づけになる。
> **現行実装（モック）には未実装。**


> **区分の切り替え**
> - **請求**（初期値）… `t_billing_partners` の取引先だけを表示する。
> - **全て** … 請求に加えて `t_payable_partners`（支払）の取引先も**同じ一覧に並べる**。
>   支払行は承認ステータスに関わらず**表示のみ**で操作できない（サーバが `operable = false` を返す）。
>   また **絞り込みはすべて請求（自区分）の行にのみ適用**し、支払行は絞り込まない。
>   自区分にヒットが無い項目は支払行ごと非表示になる（共通仕様 §3.3）。

### 表示する承認ステータス

| ステータス | 意味 |
| --- | --- |
| `APPLIED` | 申請中（承認待ち） |

### 表示ステータス以外のデータの扱い

| ステータス | 挙動 |
| --- | --- |
| `DRAFT`（未申請） | 承認・否認できない |
| `APPROVED`（承認済） | 承認・否認できない |
| `CANCEL_APPLIED`（取消申請中） | 承認・否認できない |
| `CANCELLED`（取消承認済） | 承認・否認できない |

### 業者マイページ側の操作

**見積内容を確認し、「発注承諾」のボタンを押下する。**
承諾されると発注テーブルへ登録される（→ §8.5）。

## 8.5 操作 → データ更新先

> 出典: **見積管理_処理フロー**（G列「データ更新先」）。
> 表の「更新先」はスプレッドシートの記述をそのまま構造化したもの。現行実装との差異は下の注記に記す。

| 操作 | 更新先 |
| --- | --- |
| **承認** | 業者マイページに見積書を表示し、通知（確認依頼）メールを送信<br>請求取引先（`t_billing_partners`）の承認ステータスを更新（`APPLIED` → `APPROVED`）<br>**発注のテーブルに登録** ※テーブル未決 |
| **否認** | 差し戻し（「【請求】見積作成」画面に表示）<br>請求取引先（`t_billing_partners`）の承認ステータスを更新<br>コメント（`t_comments`）に登録 |

> **確定した事項**: 発注レコードの作成タイミングは**部長の見積承認時**（業者の「発注承諾」押下時ではない）。
> ただし登録先の**テーブルは未決**（支払側の `t_payable_orders` も未作成）。
>
> **確定した事項**: 否認時の差し戻し先は **【請求】見積作成画面**。もらいは業者選定が無いため、
> 承認ステータスは `DRAFT` に戻して見積入力からやり直す想定。

**現行実装（モック）との差異**

- 否認ボタン、通知メール送信、発注テーブルへの登録はいずれも未実装。

## 9. 留意事項・未確定事項

- **見積承認後の金額の追加・修正を不可にするか** → 【請求】見積作成側の**承認申請で編集をロック**する
  （処理フロー準拠。→ [06_請求_見積作成](./06_請求_見積作成_詳細設計.md) §8.5）。承認後の再修正可否は引き続き未確定。
- ~~部長が否認した場合の差し戻し先~~ → **確定**: 【請求】見積作成画面へ差し戻す（§8.5）。
- ~~発注（Order）レコードの作成タイミング~~ → **確定**: **部長の見積承認時**に登録する（§8.5）。
  ただし**登録先テーブルは未決**（支払側の `t_payable_orders` も未作成）。
- ⑤ の時点で担当者から修正依頼をしたい場合は、【請求】見積取消申請を使う
  （→ [08_請求_見積取消申請](./08_請求_見積取消申請_詳細設計.md)）。
