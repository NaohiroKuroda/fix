## 2026-09-08

| # | 症状 | 原因 | 修正 |
| :-- | :-- | :-- | :-- |
| B9 | 実行予算の作成・同期時に `t_building_budget_items` への INSERT が SQL エラー（`sort` が存在しない） | felix_total 側で `sort` → `sort_order` へ改称するマイグレーション（`2026_09_07_110000_rename_sort_to_sort_order_on_t_building_budget_items_table`）を入れたが、参照側のコードが追随していなかった | **fix**: `TBuildingBudgetItem::$fillable`、`PayableRepository` / `BillingRepository` / `OrderDeliveryRepository` の `orderBy('sort')`、`QuoteRequestMockSeeder`<br>**felix_total**: `TBuildingBudgetItem::$fillable`、`NewQuotationRegisterService::fillBudgetItemColumns()`（右辺の `$unit->sort` は現行 `estimate_units` の列なのでそのまま）、`NewEstimateTestDataSeeder` |
| B10 | 部長承認で**1社を否認**したら、同じ項目に並ぶ**他の見積先まで**業者選定画面で赤くなり、赤バッヂも項目内の全見積先ぶん（1社否認したのに 7）に膨らむ | 否認済みかどうかを「項目（`t_building_budget_items`）のコメントに `【否認】` で始まる投稿があるか」で判定していた。コメントは項目単位のスレッドなので見積先を区別できず、取消否認（差し戻しではないが `【否認】` を残す）でも赤くなっていた | 差し戻し先を `DRAFT` と分けて **`REJECTED`**（否認差し戻し）にし、赤表示・赤バッヂはステータスで判定する（列の追加はしない）。請求側も同じ問題（否認・取消承認がどちらも `CANCELLED`）だったので `APPLIED` → `REJECTED` に揃えた。再申請（`APPLIED`）で解消。支払は**同じ項目で誰かを選び直した時点**でも `DRAFT` に戻す（画面の赤→緑と同じ扱い） |
| B11 | 見積依頼画面で再依頼するとサーバーエラー（felix_total が HTTP 500）。依頼履歴の同期は済んでいるのに画面はエラー表示 | 見積依頼メールを積む `EstimateCustomDetailController::send_mail()` が、メールキュー用の別DB（`mysql_2` ＝ 社内ネットワーク越しの `192.168.10.245`）への INSERT を素通しで実行していた。VPN が繋がっていないと接続タイムアウトで例外になり、**見積依頼の処理ごと 500 で落ちる**（相見積データの有無は無関係） | **felix_total**: `send_mail()` の INSERT を try/catch で包み、失敗はログに残して処理は続行（`bool` を返す）。`config/database.php` の `mysql_2` に書かれている「失敗は各処理でログに握る」方針に揃えた。呼び出しは24箇所あるが、共通の `send_mail()` 1箇所で塞げる |



> B11 の後は、メールキューへ積めなくても見積依頼自体は成功する。**メールが飛んでいないことはログ
> （`メールキューへの登録に失敗しました`）でしか分からない**ので、VPN 未接続時の確認はログを見ること。
> B10 は DB のスキーマ変更なし（`approval_status` は文字列列）。
> ただし**修正前に否認された既存データは `DRAFT` / `CANCELLED` のまま**なので赤表示は消える。
> 遡ってどの見積先が否認されたかは特定できないため、埋め戻しはしていない（否認し直せば正しく付く）。

## 2026-09-08（追加実装）

| # | 内容 | 経緯 | 対応 |
| :-- | :-- | :-- | :-- |
| 発注連携 | 部長承認しても**業者マイページに発注書が出ず、請負承認できない** | 業者マイページの発注書一覧と請負承認は**現行 `orders`（`status >= 10`）が起点**。新Fix の部長承認は新テーブルの `t_payable_orders` を作るだけで、現行 `orders` を作っていなかった（実データでも該当 `estimate_units` の `orders` は0件） | 部長承認で現行 `create_send_order_company` を呼び、`orders` ＋ `order_units` を作成 → `status = 10` → 発注メール（`FelixTotalQuoteRequestGateway::createAndSendOrder()`）。あわせて**部長取消承認で `cancel_send_order`（`status=99`）を呼ぶ**（`cancelOrder()`）。現行APIは既存のものをそのまま利用し、felix_total 側は無変更 |

> 取消時にキャンセルするのは、`create_send_order_company` が**既存の `orders` / `estimate_customs` を再利用する**ため。

> なお支払（はらい）系の金額は常に現行が起点（業者が現行の業者マイページで入力 → 新テーブルへ同期）で、
> 新→現行の金額連携は無い（請求＝もらい側だけは見積承認時に現行へ写す）。
