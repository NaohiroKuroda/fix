## 3. 新しく見つかった不具合

### B6 🔴 部長ロールでは felix_total 連携が「成功」扱いで無言に失敗する

**現象**

- 【請求】見積承認（`manager_test` で実行）→ 現行への同期 API を叩くが、`estimate_unit_company_files` が作られない。エラーも出ない。
- 【支払】部長承認 → 建設部選定（`update_tmp_company_select_flg`）も同様に効いていない（`estimate_units.tmp_company_id` は NULL のまま）。

**原因（実測で確定）**

felix_total のアクセスログで、同じ API でも**呼び出したユーザーによって応答サイズが違う**。

```
07:14:52 update_adoption_flg           200  1,458   ← engineer_test（成功）
07:17:47 update_tmp_company_select_flg 200 50,669   ← manager_test（失敗）
07:23:57 sync_billing_quotation        200 50,662   ← manager_test（失敗）
```

manager_test（`admin_roles.slug = tmp`）の cross_auth クッキーを付けて同じ URL を叩くと、
**laravel-admin の「権限がありません」ページが HTTP 200 で返る**ことを確認した。

```
status=200 size=50432 → 本文に「権限がありません」
```

新Fix 側のゲートウェイは **HTTP ステータスしか見ていない**ため、これを成功として扱う。

`app/Services/FelixTotal/FelixTotalQuoteRequestGateway.php:189`

```php
if (! $response->successful()) {   // 200 なので通過してしまう
    throw new RuntimeException(...);
}
```

見積依頼（`orderEstimate`）だけは `$response->json() === null` も見ているため検知できるが、
`callEdit()`（採用 / 建設部選定 / 解除）と請求見積の同期にはこのチェックが無い。

**影響**

- 部長ロールのアカウントでは、**部長承認の建設部選定と【請求】見積承認の現行同期が黙って失敗する**。
- 業者マイページに見積が出ないため、**もらいのフローが業者側で止まる**（今回は手動同期して先へ進めた）。
- 画面には成功トーストが出るので、担当者は失敗に気づけない。

**直し方（2点)**

1. **新Fix 側**: `callEdit()` と同期呼び出しでも `$response->json() === null` を失敗として扱う
   （HTML が返ってきたら例外にする）。これがあれば少なくとも「無言の失敗」は無くなる。
2. **felix_total 側**: 部長ロール（`tmp` / `engineer_manager`）に `new-estimates-custom-edit` の権限を与える。
   もしくは cross_auth 経由のサーバ間 API を権限チェックの対象外にする。

> 今回は `admin_roles` に `engineer_manager` が無かったため、manager_test に `tmp` を割り当てて実施した。
> 本番相当のロール構成でも同じ問題が起きるか、`engineer_manager` の権限設定とあわせて確認が必要。

## 5. ⚠️ 本テスト中に発生した事故と復旧

**事故**: 修正後に `php artisan test` を実行したところ、共有DB `fix` が全テーブル DROP されました（2026-09-04 06:20:50 UTC）。

- 原因: `tests/Feature/HasBlameColumnsTest.php` の `RefreshDatabase` が mysql 接続で `migrate:fresh` を実行。
- `phpunit.xml` の `force="true"` は **`new_fix_dev` コンテナの実環境変数（`DB_CONNECTION=mysql` / `DB_DATABASE=fix`）に負けており、効いていませんでした**。
- binlog が OFF のためポイントインタイム復旧は不可。

**復旧**: ユーザーから提供された `itplus4_total.sql`（2.56GB / 2026-09-04 15:38）をインポートし、
felix_total の未適用マイグレーション（`t_*` / `m_*` の新見積管理テーブル 30本）を実行して再構築しました。

- 旧テーブル 395件を復元（`admin_users` 313 / `estimates` 631 / `estimate_units` 398,155 /
  `estimate_unit_companies` 665,797 / `companies` 60,132 ほか）。
- 途中 `max_allowed_packet`（4MB）超過で `witness_data` 以降が止まったため、
  1GB に引き上げて末尾を再投入。全 405 テーブルが揃っています。
- `t_*` は**マイグレーションで作り直したため空**。ご要望の「t_ で始まるデータの削除」もこれで満たしています。
- テストアカウントは復元ダンプに含まれないため作り直しました（`engineer_test` = `engineer` /
  `manager_test` = `tmp`。`engineer_manager` ロールは復元後の `admin_roles` に存在しないため `tmp` を使用）。

**再発防止**: `tests/TestCase.php` に、テストが sqlite 以外へ接続していたら即座に例外を投げるガードを入れました。
設定ではなく接続先そのものを実行時に検査します。
