> [共通仕様_詳細設計.md](./00_共通仕様_詳細設計.md) を参照。本書は本画面固有の差分を記述する。
>
> 出典: [`docs/operations/もらい_運用フロー.drawio`](../../operations/もらい_運用フロー.drawio)（①〜③）／
> テーブル定義書（`t_billing_partners` / `t_billing_quotations` / `t_billing_quotation_details`）。
> ※ テーブル定義書の表記は `t_billing_quotation_ditails` だが、実 DB の物理名は

## 1. 概要

- **画面名**: 【請求】見積作成【FELIX(担当者)→業者】
- **区分**: 請求＝「もらい」（FELIX が請求する側のフロー）／**新規画面**
- **mode**: `billing-quote-create`
- **操作ロール**: 建設部担当者（`staff_role_slugs`）、administrator
- **目的**: もらい（請求先）として登録した取引先に対し、FELIX 側で**見積を代理作成**する。
  作成・保存すると部長承認待ち（`APPLIED`）へ進む。

### 1.1 「もらい」の前提（重要）

- もらいレコードを作成する時点で、**業者と金額のすり合わせは TEL で完了している**。
  したがって**相見積・業者選定は発生しない**（業者から見積が返ってくるステップが無い）。
- 本来のもらいは「業者が発注者」だが、Fix では画面・データの向きを**はらい（支払）と同じ
  FELIX→業者に揃え**、見積依頼と発注を FELIX 側で**自作自演**で登録する。
  請求だけが FELIX→業者（＝FELIX が請求する側）になる。
- もらい／はらいの判定は現行 `estimate_unit_companies.invoice_flg`。
  新スキーマでは**テーブルごと分離**され、支払＝`t_payable_partners` / 請求＝`t_billing_partners` になる。

業務フロー上の位置づけ:

```
現行Fix 実行予算作成 ──実行予算データ──▶ ①【請求】見積作成（一覧表示）
現行Fix 項目追加     ──項目データ──────▶ ②業者追加（「請求先にする」ON＝もらい）
                                            │
                                            ▼
                              ③ 見積作成モーダル（見積額入力・保存）
                                            │
                                            ▼
                                  ④【請求】見積承認（部長）
```

取消承認された見積は本画面（③ 見積作成）へ差し戻される（→ [09_請求_見積取消承認](./09_請求_見積取消承認_詳細設計.md)）。

## 6. ③ 見積作成モーダル（⭐️新規）

### 6.1 フロー

1. 明細行の「見積作成」ボタンを押す。
2. モーダルで見積日・明細・金額を入力する。
3. 「保存」で確定 → `t_billing_quotations`（＋明細）を作成し、`approval_status` を
   `DRAFT → APPLIED` へ進める。
4. 一覧を再取得し、当該行は本画面の抽出条件から外れる（→【請求】見積承認へ）。

### 6.2 入力項目

列構成は **felix_total の業者マイページ「見積」タブ**（`resources/views/pages/estimate/_estimate_table.blade.php`）
を踏襲する。もらいは FELIX が業者に代わって同じ内容を入力するため、項目を揃えて齟齬を防ぐ。

**ヘッダー（`t_billing_quotations`）**

| 画面ラベル | カラム | 型 / 必須 | 備考 |
| --- | --- | --- | --- |
| 日付 | `quotation_date` | DATE / **必須** | felix_total の「日付」 |
| 見積書ファイル | `file_url` | VARCHAR(255) / 任意 | **端末からアップロード**（felix_total の見積タブと同じ `input[type=file]`）。保存先のURLを `file_url` に格納する。上限 10MB（[99_添付ファイル_詳細設計](./99_添付ファイル_詳細設計.md) §2 に準拠）。アップロード済みの場合はリンクを表示し、差し替えなければ既存URLを維持する |
| コメント | `comment` | TEXT | felix_total の「コメント」 |
| （自動）税別合計 | `amount_excluding_tax` | BIGINT | 明細から算出（§6.4） |
| 課税（10%） | → `tax_adjust` | BIGINT | 表示は消費税額。**自動計算値との差分**を `tax_adjust` に保存 |
| 源泉所得及び復興特別所得税 | `withholding_income_tax` | BIGINT / 任意 | |

**明細（`t_billing_quotation_details`）** ※ 行の追加・削除ができる（felix_total の「追加」ボタン相当）

| 画面ラベル | カラム | felix_total の対応 | 備考 |
| --- | --- | --- | --- |
| メモ行 | `is_memo` | `memo_flg` | ON にすると**依頼内容以外の列を出さず、依頼内容を全列にまたいで入力**する（felix_total と同じ colspan 表示）。保存時は依頼内容以外を NULL にし、金額計算の対象外とする |
| 拠点 | `branch_code` | `branch_id` | `constant.branch_list`（全社 / 名古屋 / 東京 / 静岡 / 松本 / 三河 / 豊橋） |
| 部門 | `department_id` | `department_id` | `departments` |
| 依頼内容 | `name` | `label` | |
| 数量 | `quantity` | `amount` | |
| 単位 | `unit_id` | `unit` | `master_units` |
| 税区分 | `tax_type` / `tax_rate` | `tax`（`1.10`=課税 / `1.00`=非課税） | `TAXABLE`→`0.10` / `NON_TAXABLE`→`0.00` |
| 税種類 | `is_tax_inclusive` | `tax_in_flg` | 税別 / 税込 |
| 単価 | `unit_price` | `genka_unit` | |
| 金額 | `price` | `genka` | 数量 × 単価で自動計算。手入力も可 |
| （行フラグ） | `is_changed` | `fix_flg` | §6.2.1 |

### 6.2.1 `is_changed`（使用中の行）の扱い ★重要

felix_total は明細テーブルに**空の予備行を 30 行分あらかじめ持たせ**、入力のある行だけ
`fix_flg = 1`、空行は `fix_flg = 0` で保存している。新スキーマの `is_changed` はこれに対応する。

- **画面には `is_changed = true` の明細だけを表示する**（見積修正でモーダルを開いたとき）。
- 保存時、入力のある行は `is_changed = true`、空行は `is_changed = false` で登録する。
- メモ行は依頼内容が入っていれば使用中とみなす。

### 6.3 処理（保存）

1. 同一 `billing_partner_id` の既存 `t_billing_quotations` を `is_latest = FALSE` に更新する。
2. 新しい `t_billing_quotations` を `is_latest = TRUE` で作成する。
3. 明細を `t_billing_quotation_details` へ一括作成する。
4. `t_billing_partners.approval_status` を `DRAFT → APPLIED` へ更新する。
5. 1〜4 は 1 トランザクション（Service 層でトランザクション制御）。

> 見積は**版管理**（`is_latest`）とする。修正時は上書きせず新しい版を作る。

### 6.4 金額計算（BCMath 必須）

小数を含む計算は **`float` を使わず BCMath** で行う
（[`backend.md`](../../architecture/backend.md) §5.5、`App\Utils\Decimal` 経由）。
計算式は felix_total の見積タブ（`edit.blade.php` の `js_total_calc`）と同じにする。

| 値 | 計算 |
| --- | --- |
| 明細金額 `price` | 数量 × 単価（メモ行は対象外） |
| 行の税抜額 | 税込行は `price × 100 ÷ 110`（円未満四捨五入）、税別行は `price` |
| 税別合計 `amount_excluding_tax` | Σ 行の税抜額 |
| 消費税（自動） | 課税行の税抜合計 × `tax_rate`（円未満四捨五入） |
| 行ごと丸めの税込合計 | Σ（税込行は `price`、課税行は `price × 110 ÷ 100` 四捨五入、非課税行は `price`） |
| **消費税調整 `tax_adjust`** | 画面の消費税額 − 自動計算の消費税額<br>（既定では「行ごと丸めの税込合計 − 税別合計」との差＝端数調整。手入力したときはその差分） |
| 税込金額 | 税別合計 + 消費税額 |
| 差引支払額 | 税込金額 − 源泉所得及び復興特別所得税 |

> `tax_rate` / `share` は **string 型のまま**取り扱う（テーブル定義書の実装メモに準拠）。
> 画面側の合計は入力確認用の表示で、確定値はサーバの計算結果で上書きする
> （[`frontend.md`](../../architecture/frontend.md) §4.9）。画面側の計算も `× 0.1` のような
> 小数倍を避け、`× 10 ÷ 100` の整数演算で行う。

### 初期表示条件

- 区分が**請求**
- **承認申請をしていない**

### 絞り込み条件

> 表の見方（処理フロー I列の記法）
> - **単一選択**（`・` 区切り）… セグメント／ラジオ。**初期値**の列が画面初期表示時の選択。
> - **チェックボックス**（`・` 区切りなし）… 単独のトグル。**初期値**が ON のものは初期表示時からチェック済み。

| 項目 | 形式 | 選択肢 | 初期値 |
| --- | --- | --- | --- |
| 見積の有無 | 単一選択 | 全て / 見積作成済み / 見積未作成 | **全て** |
| コメント | 単一選択 | 全て / コメントあり / コメントなし | **全て** |

### 表示する承認ステータス

| ステータス | 意味 |
| --- | --- |
| `DRAFT` | 未申請（見積未作成・下書きの両方を含む） |
| `CANCELLED` | 取消承認済（取消承認）※取消後に作り直せるよう本画面へ戻る |

### 表示ステータス以外のデータの扱い

| ステータス | 挙動 |
| --- | --- |
| `APPLIED`（申請中） | 見積修正できない・申請できない |
| `APPROVED`（承認済） | 見積修正できない・申請できない |
| `CANCEL_APPLIED`（取消申請中） | 見積修正できない・申請できない |

> 「見積修正できない」＝ **承認申請で編集がロックされる**（§8.5）。一覧には出るが
> 見積作成/修正ボタンと承認申請ボタンを不活性にする。

### 業者マイページ側の操作

なし（業者が見るのは見積承認後）。

## 8.5 操作 → データ更新先

> 出典: **見積管理_処理フロー**（G列「データ更新先」）。
> 表の「更新先」はスプレッドシートの記述をそのまま構造化したもの。現行実装との差異は下の注記に記す。

| 操作 | 更新先 |
| --- | --- |
| **業者追加** | 請求取引先（`t_billing_partners`）に登録 |
| **見積作成** | 請求見積（`t_billing_quotations`）と請求見積明細（`t_billing_quotation_details`）に登録 |
| **見積修正** | 請求見積明細（`t_billing_quotation_details`）に**登録か更新か未確定**（§9） |
| **承認申請** | 編集をロックして承認申請（「【請求】見積承認」画面に表示）<br>請求取引先（`t_billing_partners`）の承認ステータスを更新（`DRAFT` → `APPLIED`） |

> **重要**: 「見積作成／修正」と「承認申請」は**別の操作**である。モーダルの保存だけでは承認待ちにならず、
> 明示的な承認申請で編集がロックされ、承認ステータスが `APPLIED` へ進む。

**現行実装（モック）との差異**

- モックはモーダルの「保存」で承認申請まで済ませる想定で書かれている。
  実装時は **保存（何度でも可）→ 承認申請（1回・編集ロック）** の2段構えに分けること。
- 承認申請後の編集ロック（画面上の見積作成ボタンを不活性にする等）は未実装。
