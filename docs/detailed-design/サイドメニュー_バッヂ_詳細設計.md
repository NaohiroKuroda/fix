# サイドメニュー バッヂ 詳細設計書

> サイドメニューに出す「未処理件数バッヂ」の仕様。画面横断のため本書に集約する
> （各画面の詳細設計からは本書を参照）。
>
> **本書の対象は見積管理のみ。** 完了/納品管理・請求管理のバッヂは現時点では扱わない。
>
> **発注管理はバッヂを出さない**（2026-08-31 決定）。配下の【支払】業者承諾確認・【請求】発注書確認は
> どちらも表示のみの画面で「担当者が処理すべき件数」という概念が無いため、親・子ともバッヂを持たず、
> サーバ側でも件数を数えない（`OrderDeliveryRepository::pendingCounts()`）。

## 1. 実装の所在

| 役割 | 実装 |
| --- | --- |
| 集計（支払） | `App\Repositories\Quotation\Payable\PayableRepository::pendingCounts()` |
| 集計（請求） | `App\Repositories\Quotation\Billing\BillingRepository::pendingCounts()` |
| 共有 | `App\Http\Middleware\HandleInertiaRequests::menuBadges()` → Inertia 共有プロパティ `menuBadges` |
| 表示 | `resources/js/shared/ui/layouts/AppLayout.vue` |

`menuBadges` は「メニューキー => 件数」の連想配列。メニューキーは `menuPermissions`（表示可否）と共通。

## 2. 表示ルール

- **色**
  - **緑**（`bg-green-600`）… 未処理件数。標準のバッヂ。
  - **赤**（`bg-red-500`）… 差し戻し件数。**【支払】業者選定のみ**が持つ 2 つ目のバッヂ（`badge2`）。
    ツールチップ「部長承認で否認され業者選定へ差し戻された件数」。
- **0 件は非表示**（`v-if="child.badge"`）。
- **100 件以上は `99+`** と表示する。
- **親メニューのバッヂ** … 配下の**緑バッヂの合計**。赤（差し戻し）は合算しない。
  未ログイン時・ロールで非表示の子メニューは合計に含まれない（`quotationChildren` などで絞ってから合算）。
- **評価タイミング** … Inertia の共有プロパティ。Closure で渡しているため、
  部分リロード（`router.reload({ only: [...] })`）では再評価されない。
- **集計失敗時** … 例外を握ってログに記録し `null` を返す。バッヂが全部消えるだけで画面は落ちない
  （トーストも出さない）。

## 3. 見積管理

| メニュー | バッヂ | 数える条件 |
| --- | --- | --- |
| 【支払】見積依頼 | 緑 `quote-request` | 移行済み（`source_id` あり）かつ `t_payable_quotation_requests` が 1 件も無い＝**まだ一度も相見積を依頼していない**見積先 |
| 【支払】業者選定 | 緑 `vendor-selection` | `approval_status = 'DRAFT'` かつ相見積の回答がある＝**選定できる状態で待っている**見積先 |
| 【支払】業者選定 | 赤 `vendor-selection-rejected` | `approval_status = 'DRAFT'` かつ、その項目に `【否認】` で始まるコメントがある＝**部長承認で否認されて戻ってきた**件数 |
| 【支払】部長承認 | 緑 `manager-approval` | `approval_status = 'APPLIED'`＝**部長の承認待ち** |
| 【支払】部長取消申請 | **なし** | 常時ブラウズする画面のためバッヂ対象外 |
| 【支払】部長取消承認 | 緑 `cancel-approval` | `approval_status = 'CANCEL_APPLIED'`＝**取消の承認待ち** |
| 【請求】見積作成 | 緑 `billing-quote-create` | **まだ承認申請していない**請求先（`approval_status = 'DRAFT'`） |
| 【請求】見積作成 | 赤 `billing-quote-create-rejected` | **【請求】見積承認で否認されて戻ってきた**請求先。否認されると `DRAFT` とは別のステータス（`CANCELLED`）になるため、**そのステータスが変われば赤の件数も減る** |
| 【請求】見積承認 | 緑 `billing-quote-approval` | 見積作成画面で作成した見積を**申請済みで、まだ承認も否認もしていない**請求先（`approval_status = 'APPLIED'`） |
| 【請求】見積取消申請 | **なし** | 緑・赤とも表示しない（常時ブラウズする画面のため） |
| 【請求】見積取消承認 | 緑 `billing-cancel-approval` | **取消申請されていて、まだ承認も否認もしていない**請求先（`approval_status = 'CANCEL_APPLIED'`） |

> **赤バッヂの判定について**: 新スキーマに否認理由の列（旧 `deny_comment`）が無いため、
> 項目のコメントスレッドに `【否認】` で始まる投稿があることをもって否認済みと判定する
> （`PayableRepository::denialItemIds()`）。請求側も同じ判定方法を用いる。
>
> 請求側の集計は `BillingRepository::pendingCounts()`。

## 4. 既知の課題

- **業者選定の緑バッヂの「回答あり」判定**
  `whereHas('quotations', fn ($h) => $h->whereNotNull('is_latest'))` としているが、
  `t_payable_quotations.is_latest` は `NOT NULL` 列のため条件が**常に真**になる。
  実際は「相見積履歴が 1 件でもあるか」で数えており、本来の「最新回答（`is_latest = 1`）を持つか」
  になっていない。一覧側の回答状態フィルタ（`answer`）も同じ書き方のため同じズレがある。
  → `where('is_latest', true)` に直す必要がある（未修正）。
