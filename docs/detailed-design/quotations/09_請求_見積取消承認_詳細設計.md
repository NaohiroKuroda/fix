> 共通の仕組み（ヘッダー / フィルタ / やり取り / iframe / テーマ / 送信・エラー方針）は
> [共通仕様_詳細設計.md](./00_共通仕様_詳細設計.md) を参照。本書は本画面固有の差分を記述する。
>
> 出典: [`docs/operations/もらい_運用フロー.drawio`](../../operations/もらい_運用フロー.drawio)。
> 実データ接続済み（`t_billing_partners` / `t_billing_quotations` / `t_billing_quotation_details`）。

## 1. 概要

- **画面名**: 【請求】見積取消承認【FELIX(建設部部長)→FELIX(担当者)】
- **区分**: 請求＝「もらい」／**新規画面**
- **mode**: `billing-cancel-approval`
- **操作ロール**: 建設部部長（`manager_role_slugs`）、administrator
- **目的**: 担当者が申請した取消（`CANCEL_APPLIED`）を部長が**承認**または**否認**する。
  - **承認** … **③【請求】見積作成へ差し戻し**、見積入力からやり直しになる。
  - **否認** … `CANCELLED` にして **③【請求】見積作成へ差し戻す**（承認と同じ差し戻し先。
    否認理由がコメントに残る点だけが異なる）。

業務フロー上の位置づけ:

```
見積取消申請（CANCEL_APPLIED）──▶【見積取消承認】──承認──▶ ③ 見積作成からやり直し
                                              └──否認──▶ CANCELLED → ③ 見積作成（理由をコメントに記録）
```

> もらいは業者選定が不要なため、差し戻し先は**「見積作成からやり直し」に揃える**
>（部長が否認した場合の差し戻しも同じ扱いにする案）。

## 6. 操作仕様（取消承認・1件ずつ理由必須）

### 6.1 フロー

1. 明細行の「取消承認」を押す → 理由入力モーダルが開く。
2. 理由を入力して OK。
3. `t_billing_partners.approval_status` を `CANCEL_APPLIED → CANCELLED` へ更新する。
4. **③ 見積作成へ差し戻す**（§6.4）。
5. 対象項目のコメントスレッドへ `【取消承認】{理由}` を部長の発言として自動投稿する。

### 6.2 入力

| 項目 | 必須 | 備考 |
| --- | --- | --- |
| 対象 | ○ | 行から自動設定（請求取引先ID） |
| 理由 | ○ | テキスト。コメントに記録する |

### 6.3 応答

- 成功: `back()->with('success', "取消承認を実行しました。（n件）")`
- 0件: `back()->with('error', '取消承認を実行できませんでした。対象の請求先をご確認ください。')`
- 例外: `ServiceException` → トースト

### 6.4 差し戻し（見積作成からやり直し）

取消承認後、当該請求先を **③【請求】見積作成の対象へ戻す**。

| 対象 | 処理 |
| --- | --- |
| `t_billing_partners.approval_status` | **`CANCELLED`**（③【請求】見積作成は `DRAFT` / `CANCELLED` を操作対象にするため、これで同画面へ戻る） |
| `t_billing_quotations` | 既存の版は残す。`is_latest` の扱い（残す / 落とす）は未確定（§9） |

> **確定**: `DRAFT` に戻すのではなく `CANCELLED` のまま ③ に出す。承認・否認とも同じ。

### 6.5 否認（見積作成へ差し戻し・1件ずつ理由必須）

否認しても**差し戻し先は承認と同じ ③【請求】見積作成**で、ステータスも **`CANCELLED`** にする。
違いは、否認理由が当該項目のコメントスレッドに残る点。

1. 明細行の「否認」を押す → 否認理由モーダル（赤系「否認（見積作成へ差し戻し）」）が開く。
2. 理由を入力して「否認する」。
3. `t_billing_partners.approval_status` を `CANCEL_APPLIED → CANCELLED` へ更新する。
   ③【請求】見積作成は `DRAFT` / `CANCELLED` を操作対象にするため、これで同画面へ戻る。
4. 対象項目のコメントスレッドへ `【否認】{理由}` を部長の発言として自動投稿する。

| 項目 | 必須 | 備考 |
| --- | --- | --- |
| `partnerIds` | ○ | 行から自動設定（請求取引先ID・1件） |
| `reason` | ○ | テキスト・最大1000字。コメントに記録する |

- 成功: `back()->with('success', "取消申請を否認しました。見積作成へ差し戻しました。（n件）")`
- 0件: `back()->with('error', '否認できませんでした。対象の請求先をご確認ください。')`

## 8.4 画面の表示条件

> 出典: **見積管理_処理フロー**（H列 初期表示条件 / I列 絞り込み条件 / J列 表示承認ステータス /
> K列 ステータス外表示形式 / L列 業者マイページ）。

### 初期表示条件

- 区分が**請求**
- **取消申請された項目と業者**

### 絞り込み条件

> 表の見方（処理フロー I列の記法）
> - **単一選択**（`・` 区切り）… セグメント／ラジオ。**初期値**の列が画面初期表示時の選択。
> - **チェックボックス**（`・` 区切りなし）… 単独のトグル。**初期値**が ON のものは初期表示時からチェック済み。

| 項目 | 形式 | 選択肢 | 初期値 |
| --- | --- | --- | --- |
| 区分 | 単一選択 | 全て / 請求 | **請求** |
| 承認可能 | チェックボックス | — | **ON** |
| コメント | 単一選択 | 全て / コメントあり / コメントなし | **全て** |

> **「承認可能」チェックボックス**（`operableFilterLabel`）
> - 初期表示は **ON**。承認・否認のいずれかができる行（`operable` ＝承認ステータス `CANCEL_APPLIED`）
>   だけを表示する。
> - チェックを外すと**全件表示**（未申請・承認済みなど他ステータスの行も並ぶ。操作は不可）。


> **区分の切り替え**
> - **請求**（初期値）… `t_billing_partners` の取引先だけを表示する。
> - **全て** … 請求に加えて `t_payable_partners`（支払）の取引先も**同じ一覧に並べる**。
>   支払行は承認ステータスに関わらず**表示のみ**で操作できない（サーバが `operable = false` を返す）。
>   また **絞り込みはすべて請求（自区分）の行にのみ適用**し、支払行は絞り込まない。
>   自区分にヒットが無い項目は支払行ごと非表示になる（共通仕様 §3.3）。

### 表示する承認ステータス

| ステータス | 意味 |
| --- | --- |
| `CANCEL_APPLIED` | 取消申請中（取消承認待ち） |

### 表示ステータス以外のデータの扱い

| ステータス | 挙動 |
| --- | --- |
| `DRAFT`（未申請） | 承認・否認できない |
| `APPLIED`（申請中） | 承認・否認できない |
| `APPROVED`（承認済） | 承認・否認できない |
| `CANCELLED`（取消承認済） | 承認・否認できない |

### 業者マイページ側の操作

なし。

## 8.5 操作 → データ更新先

> 出典: **見積管理_処理フロー**（G列「データ更新先」）。
> 表の「更新先」はスプレッドシートの記述をそのまま構造化したもの。現行実装との差異は下の注記に記す。

| 操作 | 更新先 |
| --- | --- |
| **取消承認** | 請求取引先（`t_billing_partners`）の承認ステータスを更新（`CANCEL_APPLIED` → `CANCELLED`） |
| **取消否認** | 請求取引先（`t_billing_partners`）の承認ステータスを更新<br>コメント（`t_comments`）に登録 |

> 取消否認の行はスプレッドシートで一部が見切れていたため、**支払側（部長取消承認）と同じ構成**として記載している。
> 差異があれば処理フロー側を正として本書を更新すること。

**現行実装との差異**

- 承認（`【取消承認】` コメント）・否認（`【否認】` コメント）とも実装済み。どちらも
  `CANCEL_APPLIED → CANCELLED` で ③ 見積作成へ差し戻す。
- 業者マイページ側へ反映済みの見積の取り消し（felix_total 連携）は未実装（§7・§9）。
