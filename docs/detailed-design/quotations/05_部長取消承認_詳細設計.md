# 部長取消承認 詳細設計書

> 共通の仕組み（ヘッダー / フィルタ / やり取り / iframe / テーマ / 送信・エラー方針）は
> [共通仕様_詳細設計.md](./00_共通仕様_詳細設計.md) を参照。本書は本画面固有の差分を記述する。

## 1. 概要

- **画面名**: 部長取消承認【FELIX(建設部部長)→FELIX(担当者)】
- **mode**: `cancel-approval`
- **操作ロール**: 建設部部長、建設承認、administrator
- **目的**: 担当が申請した取消（取消申請中＝`CANCEL_REQUESTED`）を部長が**承認**する。
  承認すると設計部承認済（`APPROVED`＝取消承認＝完了扱い）へ進む。理由の入力を必須とする。

業務フロー上の位置づけ:

```
… ──▶ 部長取消申請 ──▶【部長取消承認】──承認──▶ APPROVED（完了）
```

## 2. 機能説明

本画面の操作は、**画面上部の「絞り込み・操作バー」のボタン**と、**明細（各行）のボタン**の
2つのボタン群から行う。以下ではボタンごとに実行される処理を分けて記載する。

前提となる一覧表示: 取消申請中（`CANCEL_REQUESTED`）の見積先を「実行予算 → 項目 → 見積先」の明細で
一覧表示する。見積額は確定見積を表示する。本画面は**1レコードごとに理由入力モーダルで単体実行**する
方式のため、ヘッダーの一括アクションボタン・「全て選択」は出さない。（→ §4, §5）

### 2.1 絞り込み・操作バーのボタン（画面上部）

| ボタン / 操作 | 実行される処理 | 参照 |
| --- | --- | --- |
| 絞り込み（検索） | 実行予算名 / 項目名 / 見積先名でサーバ側フィルタし、一覧を再取得する。 | 共通仕様 §3 |
| コメント有無フィルタ | 全て / コメントあり / コメントなしでサーバ側フィルタする。 | 共通仕様 §3 |
| 明細を全て開く / 閉じる | 全実行予算カードの明細を一括で開閉する。 | §5 |

> 本画面は per-row 方式（`isPerRowAction`）のため、「全て選択」「一括アクション」ボタン、
> および「回答状態フィルタ」は表示しない。

**検索項目（絞り込み検索フォーム）**: 下記3項目を入力し「絞り込み検索」ボタンで送信すると、
条件に一致する一覧をサーバから再取得する。いずれも**部分一致（LIKE）**で、空欄の項目は条件から除外する。

| 入力欄（画面ラベル） | 検索対象 | 条件 |
| --- | --- | --- |
| 物件名 | 実行予算名（`t_buildings.building_name`） | 部分一致 |
| 項目名 | 費用項目名（`t_building_cost_items.item_name`） | 部分一致 |
| 見積先 | 見積先の会社名（`company_name`） | 部分一致 |

### 2.2 明細のボタン（各行）

| ボタン / 操作 | 実行される処理 | 参照 |
| --- | --- | --- |
| 取消承認 | 押下で理由入力モーダルを開き、理由を入力して1件ずつ取消を承認する（`APPROVED` へ）。 | §6 |
| やり取り（吹き出し） | 項目単位のコメントスレッドを開き、建設部メンバー⇔部長でやり取りする。未読バッヂ・添付に対応。 | 共通仕様 §4 |
| 見積先の詳細（会社名リンク） | felix_total の見積先編集画面を iframe モーダルで開く。 | 共通仕様 §5 |

## 3. ルーティング / レイヤ

| 種別 | ルート名 | メソッド | 実装 |
| --- | --- | --- | --- |
| 一覧 | `quotation-management.cancel-approval` | GET | `CancelApprovalController::index` |
| 承認 | `quotation-management.cancel-approval.confirm` | POST | `CancelApprovalController::confirm` |

- ページ: `resources/js/pages/QuotationManagement/CancelApproval.vue`。
- Service: `CancelApprovalService`（`paginate` / `confirm`。`QuotationCommentService` を DI）。
- Repository: `BuildingQuotationRepository`（`recordCancelApprovals` = `advanceStatus(CANCEL_REQUESTED → APPROVED)` / `itemIdForQuotation`）。

## 4. 表示データ・抽出条件

- 対象ステータス: `approval_status = CANCEL_REQUESTED`（取消申請中）。
- 見積額列は**確定見積**（`quoteColumnLabel = '確定見積'`。項目の `quotation_amount`）。
- 回答状態フィルタ（`answer`）は使わない。

主な行フィールド:

| フィールド | 内容 |
| --- | --- |
| `cancelApproved` | 取消承認済みか（`approval_status === APPROVED`） |
| `quotePrice` | 確定見積（項目の `quotation_amount`） |

## 5. 画面レイアウト（明細テーブルの列）

| 列 | 内容 |
| --- | --- |
| 項目 | 項目名（表示中の先頭行のみ）＋ やり取り吹き出し |
| 見積先 | 会社名（iframeで詳細表示） |
| 標準単価(税抜) | `masterPrice` |
| 予算単価(税抜) | `budgetPrice` |
| 確定見積(税抜) | `quotePrice` |
| 取消承認 | 行アクションボタン（`kind=pick-button` ＋ 1件ずつ理由モーダル。押下=`取消承認`） |

- 部長取消申請と同様、**1レコードごとに理由入力モーダル → OK で単体実行**（`isPerRowAction=true`）。
  ヘッダーの一括アクション・「全て選択」は出さない。

## 6. 操作仕様（取消承認・1件ずつ理由必須）

### 6.1 フロー

1. 行の「取消承認」ボタン → 理由入力モーダルを開く（対象1件）。
2. 理由を入力し OK → `CancelActionRequest` を POST。
3. `CancelApprovalService::confirm($companyIds, $reason)`。

### 6.2 入力（`CancelActionRequest`）

- `companyIds`: required / array / min:1
- `companyIds.*`: integer / distinct / `exists:t_cost_quotations,id`
- `reason`: required / string / max:1000（**理由は必須**）

### 6.3 処理（`recordCancelApprovals`）

- `advanceStatus`: `approval_status` が `CANCEL_REQUESTED` の行のみ `APPROVED` へ UPDATE
  （実際に `CANCEL_REQUESTED` だった件数を返す）。
- 承認成功時（件数 > 0）、対象見積先が属する項目（重複排除）のコメントスレッドへ
  `【取消承認】{理由}` を操作者（部長）の発言として自動投稿する。

### 6.4 応答

- 成功: `back()->with('success', "取消承認を実行しました。（n件）")`。
- 0件: `back()->with('error', '取消承認を実行できませんでした。対象の見積先をご確認ください。')`。
- 例外: `ServiceException` → トースト。

理由モーダル UI（`actionModalOpen`）:
- ゴールド系配色。見積先名を明示し「{取消承認}します」と案内。理由未入力・送信中は OK を無効化。

## 7. 共通機能の利用

- **やり取り（コメント）**: 全画面共通。部長（manager）視点で発言（共通仕様 §4）。取消承認理由もここに残る。
- **iframe モーダル**: 「見積先の詳細」（会社名リンク）（共通仕様 §5）。
- **フィルタ**: `keyword` / `itemLabel` / `vendor` / `comment`（`answer` は未使用）（共通仕様 §3）。

## 8. 留意事項

- 取消承認により `APPROVED` に到達し、見積先のワークフローは完了扱いとなる（以降どの画面にも現れない）。
- ステータス遷移は新スキーマの直接 UPDATE で行う（felix_total 連携は伴わない）。
